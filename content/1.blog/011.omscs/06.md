## 前言

2026 年的暑假，我修了 **_CS 6250 - Computer Networks_**。

春天連修了 KBAI 和 Game AI 兩堂課之後，我想找一堂輕鬆一點的暑期課，一方面讓自己喘口氣，一方面把 free elective 的學分補上。而電腦網路正好是我一直想補的一塊。做了這麼多年的 web service，其實我對 TCP 之下發生的事一直是半知半解。封包是怎麼從我的筆電走到雲端的機房？路由器到底在做什麼決定？這些問題我平常都當作黑盒子。這堂課就是把黑盒子打開來看。

我是 2026 Summer 的學生。暑期是短學期，課程內容和作業可能每學期有所不同。

---

## 課程內容

Summer 是 11 週左右的壓縮學期，但課程內容跟正常學期一樣，一共 12 個 lesson，大致分成四塊：

- **基礎架構**：OSI 七層 vs Internet 五層模型、encapsulation、end-to-end principle。接著是 transport layer 的 TCP 三向握手、flow control 和 congestion control。
- **Routing**：intradomain 的 Link-State 跟 Distance-Vector，然後往上到 interdomain 的 BGP<sup>\[1\]</sup>。AS<sup>\[2\]</sup> 之間的 customer-provider 和 peering 關係，怎麼決定封包實際走的路。
- **Router 設計與 SDN**：router 裡面的 switching fabric 和 packet classification 演算法，然後是 SDN<sup>\[3\]</sup> 怎麼把 control plane 從硬體拆出來，用 OpenFlow 集中管理。
- **應用與現實世界**：internet security（DNS 濫用、BGP hijacking、DDoS）、網路審查與監控（DNS poisoning、TCP RST injection、DPI）、影音串流的 adaptive bitrate、以及 CDN 和 overlay network。

::footnote-block
\[1\] Border Gateway Protocol，網際網路上不同網路之間交換路由資訊的協定，決定封包跨網路時實際走的路徑。  
\[2\] Autonomous System，由單一組織管理的一組 IP 網路，例如一家 ISP 或一家雲端服務商。  
\[3\] Software-Defined Networking，把網路的控制邏輯從硬體設備抽出來、集中在軟體裡管理的架構。
::

說實話，我修這堂課最大的收穫不是某個演算法，而是 BGP 那一章。以前我以為封包走的是「最短路徑」，其實不是。AS 之間是商業關係，封包走的是「最便宜的路徑」。Customer 付錢給 provider，同等級的 ISP 之間 settlement-free peering，而路由決策先看 business policy，再看路徑長短。知道這件事之後，再看雲端服務商寫的網路架構文章，突然就都看得懂了。

SDN 那兩章也很值得。如果你在工作上碰過 Kubernetes 的 CNI 或是 service mesh，你會發現那些概念在這裡都能找到源頭。

## 專案

一共四個專案加一個 extra credit，全部用 Python 3.11，全部由 autograder 自動評分。程式量都不大，每個專案的核心程式碼大概都在 100 行以內。

1. **Spanning Tree Protocol**：模擬多台 switch 選出 root，然後把會造成迴圈的 port 關掉。不需要 VM，開學第一週就可以寫。
2. **Distance Vector Routing**：實作 distance-vector 演算法，讓每個 node 跟鄰居交換路由表直到收斂。
3. **SDN Firewall**：要在 Mininet<sup>\[4\]</sup> VM 裡跑，用 POX controller 寫 OpenFlow 規則，依照設定檔決定哪些流量放行、哪些擋掉。四個專案裡環境設定最花時間的一個。
4. **BGP Measurements**：用真實的 BGP 路由資料做分析，看 AS 數量、prefix 成長、路徑長度這些指標的變化。

::footnote-block
\[4\] Mininet，一個在單一台電腦上模擬整個虛擬網路（host、switch、link）的工具，常用來做 SDN 實驗。
::

專案的難度在 OMSCS 裡算是入門級。把觀念搞懂之後，每個專案大概幾個小時就能寫完。唯一比較花時間的是 SDN Firewall，因為指令都要直接在 VM 裡面操作，還要開 Wireshark 抓封包、開好幾個 shell 模擬不同的 host，來回切換比寫程式本身還累。而其他三個專案，真正花時間的不是演算法，是 autograder 的邊界條件：tie-breaking 的順序、輸出格式這些。Ed 討論區上有很多人踩過的坑，先看一遍再動手可以省不少時間。

## 考試

每個 lesson 後面有 quiz，考試則是有 proctoring 的閉卷選擇題。聽起來嚴肅，但題目難度跟 quiz 差不多，都直接來自課程影片內容。如果上課筆記有整理好，考前複習筆記就夠了。我沒有買教科書。學期初訂了兩本，看了幾週的課之後發現用不到，就退掉了 😏

---

## 工作量

輕。這是我目前在 OMSCS 修過的六堂課裡最輕鬆的一堂。專案通常一個週末就能搞定，剩下的時間主要花在看課程影片和整理筆記。輕到什麼程度？暑假出門旅行的時候，我在旅館裡就把其中一個專案寫完交出去了。

不過暑期有一個要注意的地方：學期短，deadline 就密。四個專案加上 extra credit 塞在 11 週裡，大約每兩週就要交一個。不難，但不能忘。

---

## 建議

- **筆記是這堂課的核心。** 專案不難，考試也不難，但知識點很多很雜。我這學期試著用 AI 當助教，把每個 lesson 的重點整理成筆記，再把 OSI 分層、TCP 生命週期、AS 關係、router 架構這些畫成圖。花在整理上的時間，考試的時候全部賺回來。
- **Mininet VM 早點裝。** P3 是唯一需要 VM 的專案。VM 本身沒什麼難度，但第一次跑會遇到一些環境問題，不要拖到 deadline 前一天才開始。
- **鎖好 Python 版本。** 課程指定 Python 3.11，我用 conda 開了一個獨立環境，省掉很多不必要的麻煩。
- **先看 Ed 論壇再寫程式。** autograder 的隱藏測試和 tie-breaking 規則，論壇上幾乎都有人問過。
- **把 AI 當家教，不是代寫。** 專案太短，交給 AI 寫完你什麼都學不到。我用它來討論觀念、畫圖、幫我檢查邏輯，程式還是自己寫。

## 總結

如果你是做後端或 infra 的工程師，而且跟我一樣對網路層一直是半知半解，我很推薦這堂課。它不會讓你變成網路專家，但它把你每天在用的東西的底層邏輯講清楚了。以後看到 latency 飆高、DNS 出問題、或是 CDN 的 cache 行為奇怪，你至少知道該從哪一層開始想。

而如果你是在找一堂輕鬆的課來平衡另一堂重課，或是像我一樣想在暑假喘口氣，CS 6250 也是一個很好的選擇。
