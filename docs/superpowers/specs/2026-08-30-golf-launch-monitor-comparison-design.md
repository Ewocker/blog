# Golf Launch Monitor Comparison — Design

**Date:** 2026-08-30
**Status:** Approved for planning
**Route:** `blog.ewocker.com/golf`

## 1. Purpose

An interactive reference page on the blog that lets a reader compare golf
launch-monitor metrics (ball speed, smash factor, carry, spin, etc.) across
skill tiers (Beginner / Amateur / Tour Pro), for any of 17 clubs, for men and
women, in imperial or metric units. Every metric is explained via a click-to-open
dictionary modal, and a lightweight trajectory canvas visualizes the numbers.

Primary audience: blog readers (bilingual — Traditional Chinese + English).

## 2. Architecture

Self-contained static app embedded in the Nuxt blog via iframe, mirroring the
existing `career-copilot` pattern. Four artifacts:

| Artifact | Role |
|---|---|
| `public/golf/index.html` | **The entire app.** One self-contained file: HTML + inline `<style>` + inline `<script>`. Contains the embedded JSON dataset, i18n string tables, unit-conversion engine, app state, table renderer, trajectory canvas, and metric-dictionary modal. No framework, no build step; also opens standalone in any browser. |
| `layouts/golf.vue` | Thin iframe wrapper (copy of `layouts/career-copilot.vue`) pointing at `/golf/index.html`, with a short bilingual intro blurb above the frame. Adds `margin-bottom` to avoid copyright overlap, as career-copilot does. |
| `content/11.golf.md` | Content stub: frontmatter `layout: golf`, `navigation: false`, `title`, `description`, and `head.meta` (`author: 小貓貓工程師`, `read: N/A`). Nuxt Content routes it at `/golf` and applies SEO/OG tags. |
| `Projects/golf-launch-monitor-comparison.md` (Obsidian vault) | `type: project` hub note per the second-brain design spec. Created after reading `[[obsidian-second-brain-design]]` for current frontmatter/tag/link rules. Links back to this spec and the blog page. |

### Why iframe + vanilla JS (not native Vue, not React)

- User decision: standalone HTML embedded via iframe. Keeps the app portable
  and reusable outside the blog; the single file is trivially copyable.
- Vanilla JS keeps the file self-contained (no bundler) while remaining small.
- The blog's Tailwind/dark-mode styling is intentionally NOT inherited; the app
  owns its own styling (the Material red palette below).

## 3. Data model

All numbers stored in **imperial base units**; metric display is computed on the
fly from the unit toggle. Dataset shape:

```
dataset[club][gender][tier] = {
  club_speed, ball_speed, smash, launch_angle,
  height, carry, total, spin, aoa, land_angle
}
```

- `clubs` (17): Driver, 3-Wood, 5-Wood, 7-Wood, 3-Hybrid, 4-Hybrid, 3-Iron,
  4-Iron, 5-Iron, 6-Iron, 7-Iron, 8-Iron, 9-Iron, PW, GW, SW, LW
- `genders` (2): Men, Women
- `tiers` (3): `Beginner` (20+ HCP), `Amateur` (10–15 HCP), `Tour_Pro` (PGA/LPGA)

### Data sourcing

Full dataset generated by extrapolation from published TrackMan PGA/LPGA tour
averages and USGA/FlightScope handicap statistics. The app displays a visible
disclaimer that values are **reference estimates**, not the reader's own data.
The Driver row uses the exact numbers from the blueprint; remaining clubs follow
standard gapping (≈3–4 yd carry drop per iron step for amateurs, wider for pros;
loft-driven launch/spin/land-angle progressions).

## 4. Metric dictionary

13 metrics total, each with: `id`, `name`, `tier`, `formula` (where applicable),
`definition`, `shot_outcome_effect`, `common_fault` — authored in **both**
languages.

- **10 tabular metrics** (have per-tier values, shown as table rows): Club Speed,
  Ball Speed, Smash Factor, Launch Angle, Apex Height, Carry, Total, Spin Rate,
  Angle of Attack, Descent/Land Angle.
- **3 diagnostic metrics** (no per-tier table values — situational, not skill
  averages): Launch Direction, Spin Axis / Side Spin, Face-to-Path. These appear
  in the dictionary/modal only, reachable from an "explainer" list, not as table
  rows.

Clicking any metric name opens an accessible modal: title + tier badge, formula,
definition, shot-outcome effect, common fault. `ESC` closes; focus is trapped
while open; focus returns to the trigger on close.

## 5. Importance color palette (Material Design red monochrome)

Single hue; importance read by depth (darker = more critical).

| Tier | Meaning | Color | Text on badge |
|---|---|---|---|
| Tier 1 | Critical — Distance & Energy Transfer | Material **Red 900** `#B71C1C` | white |
| Tier 2 | High — Flight Window & Stopping Power | Material **Red 600** `#E53935` | white |
| Tier 3 | Diagnostic — Delivery & Curvature Mechanics | Material **Red 300** `#E57373` | dark (`#3b0a0a`) |

Tier badges appear on metric-row labels and in modal headers.

## 6. Unit conversion engine

Base imperial → computed on toggle. Precision-safe formatters.

| Quantity | Imperial (base) | Metric options | Conversion |
|---|---|---|---|
| Speed (club/ball) | mph | m/s, km/h | ×0.44704 / ×1.60934 |
| Distance (carry/total) | yd | m | ×0.9144 |
| Height (apex) | ft | m | ×0.3048 |
| Angles (launch/AoA/land) | ° | ° | identity |
| Spin | rpm | rpm | identity |

Rounding: angles & smash `toFixed(1)`; distances/height/speeds integer;
spin integer (thousands separator).

## 7. UI layout & state

State: `{ selectedClub, gender, unitSystem, activeTiers[], lang, modalMetric }`.

```
TOP BAR:  [Title]                    [Unit: Imperial | m/s | km/h]  [🌐 EN | 繁中]
CONTROL:  [Club ▾]  [Gender: (•)Men ( )Women]  [Tiers: ☑T1 ☑T2 ☑T3]
TABLE:    Metric (i) | Beginner | Amateur | Tour Pro     (tier badge per row)
TRAJECTORY: <canvas> — 3 flight arcs for selected club+gender
DISCLAIMER: reference-estimate note
MODAL:    (on metric-name click) title+badge, formula, definition, effect, fault
```

- Table: metric rows × 3 skill-tier columns. Sticky header on desktop;
  horizontal scroll on mobile. Rows filtered by `activeTiers`.
- **Language toggle** swaps all UI strings and dictionary content between English
  and Traditional Chinese. Metric names may keep English term in parentheses in
  the zh-Hant view.

## 8. Trajectory canvas (basic, data-driven)

For the selected club + gender, draw three flight arcs (one per tier) on a 2D
canvas. Each arc is shaped from that tier's `carry` (x-extent), `apex` (peak
height), and `land_angle` (steepness of descent) — a scaled asymmetric curve, not
a physics simulation. Arcs colored by the tier palette; simple axis labels
(distance / height) that respect the unit toggle. Redraws on club/gender/unit
change.

Fallback if the arc proves fiddly: a single static illustration. Not expected.

## 9. Out of scope (YAGNI)

- **Split View | Single comparison-mode toggle** — dropped. The table already
  shows all three tiers side by side.
- **Export** (CSV/image) — not in v1.
- User's own shot data entry / persistence — not in v1.

## 10. Testing

- Manual: unit toggle recomputes all cells correctly (spot-check known
  conversions); language toggle swaps every string incl. modal; tier filter
  shows/hides rows; club/gender switch updates table + canvas; modal keyboard
  (ESC + focus trap); mobile horizontal scroll.
- Build: `npm run generate` succeeds and `/golf` renders the iframe;
  `public/golf/index.html` opens standalone in a browser.
